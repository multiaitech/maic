# Documentation

Short, plain notes about how Aura behaves and how a build is checked. Every claim is meant to be checkable. When a document here and the running app disagree, the app is right and the document is the thing to fix.

- [verify-a-build.md](verify-a-build.md) - fingerprint a build you downloaded and compare it with the published hash.
- [aura-0.2.62.md](aura-0.2.62.md) - what changed in 0.2.62, how it was built, and what it does not do.
- [lesson-delete-uploaded-only.md](lesson-delete-uploaded-only.md) - which Lesson Learned records a local delete removes, and which ones stay on the PC.
- [checkpoint-retention.md](checkpoint-retention.md) - what a configuration checkpoint holds, how many are kept, and which safety snapshots are pinned.
- [coder-model-slots.md](coder-model-slots.md) - why Frontend, Backend and Coder keep separate models.

Two rules these notes follow: nothing is described as working before it has been run, and a limit is written down next to the feature instead of being left out.
